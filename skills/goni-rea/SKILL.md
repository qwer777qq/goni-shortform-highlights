# 고니 | REA 리버스 엔지니어링

[morluto/rea](https://github.com/morluto/rea)를 활용하는 고니용 운영 스킬이다. REA 원저작자는 morluto이며 엔진을 고니가 자체 개발했다고 표현하지 않는다. 스킬 설치는 MCP 연결이나 분석 엔진 설치를 의미하지 않는다.

1. 목표 기능·대상 URL/파일·현재 프로젝트를 식별한다. 개발 요청이면 현재 프로젝트에서 구현까지 이어간다. 일반 소스 코드 관계 분석만 필요한 작업에 REA를 강제로 적용하지 않는다.
2. REA MCP가 있으면 실제 노출된 도구 스키마를 사용한다. 없으면 `python scripts/rea_cli.py --help`로 설치된 공식 CLI를 사용한다. 도우미는 검증한 6.5.0 캐시를 찾아 Node로 실행하며 설치·설정 변경을 하지 않는다.
3. 웹사이트의 화면 동작, 공개 배포 코드, 허용된 네트워크 관찰을 구분한다. 소수 핵심 파일부터 분석한다. 직접 연결이 안 되면 공개 코드·기존 HAR을 활용하되 직접 런타임 관찰로 표현하지 않는다.
4. 대상에 맞는 명령·증거 판독은 [실행 절차](references/workflows.md)를 읽는다. 네이티브/모바일/펌웨어는 설치된 REA의 해당 가이드와 제공자 지원을 확인한 뒤 진행한다.
5. evidence_id, 입력 해시, 분석 버전·범위·제한·오류를 보관한다. 관찰 사실 / 정적 추론 / 미확인을 구분한다. exit 0이어도 partial/truncated이면 부분 결과다. 프런트엔드 코드만으로 서버 AI 모델·프롬프트·렌더러를 복원했다고 하지 않는다.
6. 구현까지 요청받았으면 관찰한 동작을 독립 구현하고 실제 입력→편집→출력으로 검증한다. 타사 브랜드·미디어·배포 코드를 새 제품 소스로 무단 포함하지 않는다. 조사 문서만 만들고 앱 완성으로 보고하지 않는다.

연결 문제가 실제로 있을 때만 진단한다. setup의 변경 계획·백업·스킬 교체를 확인하고 요청 범위에서 적용한다. 기존 사용자 허용을 활용하며 불필요한 재확인을 하지 않는다. 거부된 디버깅 실행을 다른 명령으로 우회하지 않는다. 계정·세션 토큰을 증빙이나 공개 저장소에 넣지 않는다.

산출물은 재현 명령, 기능/근거 표, 미확인 항목, 구현 파일, 검증 결과다. 게시·공개는 현재 사용자의 범위를 따른다.
